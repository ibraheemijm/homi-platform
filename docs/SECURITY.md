# ضوابط الأمن

## أسرار الخادم

- المفتاح الخاص Ed25519 لا يوجد في المستودع ولا في تطبيق Grocery.
- يخزن المفتاح الخاص في Cloudflare Worker Secret فقط بعد توليده خارج Git.
- مفتاح التحقق العام فقط هو ما يضمّن في بناء العميل.
- لا تستخدم مفاتيح اختبار أو أسرارًا افتراضية في بيئة الإنتاج.
- تدوير المفاتيح يجب أن يحافظ على التحقق من التراخيص القديمة ضمن سياسة موثقة.

## حماية API العامة

- تحقق صارم من أنواع الحقول وأطوالها والمنصات المسموحة.
- حد أقصى لجسم الطلب 16 KiB في المرحلة الأولى.
- تحدي عشوائي 32 بايت وصلاحيته خمس دقائق.
- التحقق من Ed25519 على الخادم قبل اعتماد إثبات الجهاز.
- تحديد معدل طلبات الإنشاء وإثبات الملكية.
- لا تُعد تفاصيل داخلية أو stack traces للعميل.
- لا تحفظ عنوان IP الخام؛ يستخدم hash لنافذة تحديد المعدل فقط.
- CORS مقيد بعنوان الموقع المسموح، ولا يعد CORS آلية مصادقة.

## لوحة الإدارة

لا توجد واجهات إدارية عامة في هذه المرحلة. يجب حماية جميع مسارات الإدارة عبر Cloudflare Access مع تحقق JWT وRBAC داخل التطبيق قبل إضافة وظائفها. لا يكفي إخفاء رابط لوحة الإدارة.

## بيانات العميل

لا تجمع بيانات المبيعات أو المخزون أو الديون. لا تضع بيانات شخصية أو ملفات تراخيص حقيقية في GitHub Issues أو Pull Requests أو الاختبارات.

## النشر

لا تنشر قبل:
1. إنشاء D1 مستقلة لكل بيئة.
2. ضبط Cloudflare Access للمسارات الإدارية.
3. إضافة أسرار التوقيع إلى بيئة Worker فقط.
4. ضبط origins وCORS بدقة.
5. مراجعة migration ونسخ احتياطي للبيانات إن وجدت.
6. مراجعة أمنية واختبارات تكامل.
