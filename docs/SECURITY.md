# ضوابط الأمن

## أسرار الخادم

- لا يوجد أي مفتاح خاص Ed25519 في المستودع أو تطبيق Grocery أو المتصفح الإداري.
- توجد ثلاثة أدوار منفصلة للمفاتيح: جذر يوقّع Keyset فقط، ومفتاح لتصاريح الترخيص Offline، ومفتاح مستقل لتوقيع بيانات تحديث التطبيقات.
- تحفظ المفاتيح الخاصة في Cloudflare Worker Secrets فقط بعد توليدها خارج Git.
- يثبت التطبيق المفتاح العام لجذر الثقة في إعدادات البناء؛ ولا يثق بالمفاتيح التشغيلية قبل التحقق من Keyset الموقع بالجذر.
- مفاتيح التحقق العامة التشغيلية تنشر بصيغة DER/SPKI داخل Keyset، ولا تعد أسرارًا.
- لا تستخدم مفاتيح اختبار أو أسرارًا افتراضية في بيئة الإنتاج.
- عند تدوير أي مفتاح تشغيلي يجب زيادة إصدار Keyset، ونشر المفتاح الجديد مع القديم كـ verify_only خلال فترة انتقال، ثم سحب القديم بعد انتهاء التواقيع القديمة.

## حماية API العامة

- تحقق صارم من أنواع الحقول وأطوالها والمنصات المسموحة.
- حد أقصى لجسم الطلب 16 KiB في المرحلة الأولى.
- تحدي عشوائي 32 بايت وصلاحيته خمس دقائق.
- التحقق من Ed25519 على الخادم قبل اعتماد إثبات الجهاز.
- تحديد معدل طلبات الإنشاء وإثبات الملكية.
- تسجيل التجربة المحلية لا يقبل إلا إثبات Ed25519 مرتبطًا ببصمة المفتاح؛ تخضع العملية لتحديد المعدل، وتُحفظ الهوية والتواريخ فقط دون إنشاء حساب عميل أو ترخيص.
- قيود D1 الفريدة تمنع التسجيل المكرر للتطبيق نفسه وفق معرف الجهاز أو بصمة المفتاح، ويعيد التكرار تاريخ التجربة الأصلي بدل إنشاء فترة جديدة.
- لا تُعد تفاصيل داخلية أو stack traces للعميل.
- لا تحفظ عنوان IP الخام؛ يستخدم hash لنافذة تحديد المعدل فقط.
- CORS مقيد بعنوان الموقع المسموح، ولا يعد CORS آلية مصادقة.

## لوحة الإدارة

لوحة الإدارة ومساراتها محمية عبر Cloudflare Access مع تحقق JWT وRBAC داخل Worker. تشمل الصلاحيات مراجعة التفعيل والمدفوعات وإدارة الإصدارات. لا يكفي إخفاء رابط لوحة الإدارة. جميع ملفات إثبات الدفع وحزم الرفع تبقى في R2 ولا تملك روابط عامة ثابتة؛ لا يتاح التنزيل العام إلا لحزمة إصدار منشورة صراحةً.

رفع الحزم يستخدم R2 Multipart Upload بأجزاء صغيرة. يحسب المتصفح SHA-256 قبل الرفع، ويوقع الخادم بيان الإصدار. يتحقق تطبيق العميل من توقيع البيان ثم من الحجم وSHA-256 الفعليين قبل إتاحة الملف للتثبيت. لذلك لا يثبت أي ملف لم يطابق البصمة الموقعة.

## بيانات العميل

لا تجمع بيانات المبيعات أو المخزون أو الديون. لا تضع بيانات شخصية أو ملفات تراخيص حقيقية في GitHub Issues أو Pull Requests أو الاختبارات.

## النشر

لا تنشر قبل:
1. إنشاء D1 مستقلة لكل بيئة.
2. ضبط Cloudflare Access للمسارات الإدارية.
3. إضافة أسرار التوقيع إلى بيئة Worker فقط.
4. ضبط origins وCORS بدقة.
5. مراجعة migration ونسخ احتياطي للبيانات إن وجدت.
6. مراجعة أمنية واختبارات تكامل.
