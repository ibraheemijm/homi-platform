# معمارية Homi Platform

## القرار التشغيلي الحالي — 25 نوفمبر 2026

تعتمد المرحلة الحالية التفعيل وتجديد الاشتراكات بالملفات فقط. لا يحتاج تطبيق العميل إلى اتصال مباشر بالمنصة لإتمام التفعيل أو التجديد.

## حدود المسؤولية

- **Homi Website:** موقع عام للتعريف بالتطبيقات وروابط التنزيل وشرح خطوات التفعيل والدعم. لا يستقبل طلبات التفعيل ولا إثباتات الدفع ولا يعرض حالة الطلب في المرحلة الحالية.
- **Homi Admin:** لوحة محمية عبر Cloudflare Access وRBAC. تستقبل ملفات `.hreq` من الإدارة، وتراجع الطلبات والمدفوعات، وتصدر ملفات `.hlic`.
- **Homi Platform API:** Cloudflare Pages Functions/Worker مع D1 وخدمة تخزين الملفات؛ تتحقق من ملفات الطلب وتدير العملاء والاشتراكات والأجهزة والتراخيص.
- **Homi Grocery:** ينشئ ملف `.hreq` محليًا ويستورد ملف `.hlic` ويتحقق من توقيعه محليًا. لا يستدعي مسارات التفعيل المباشر أو تسجيل التجربة أو تجديد Offline Grants.

## تدفق التفعيل المعتمد

1. ينشئ التطبيق ملف `.hreq` ويوقعه بمفتاح الجهاز الخاص المحفوظ في التخزين الآمن.
2. يرسل العميل الملف إلى إدارة Homi عبر وسيلة التواصل المتفق عليها.
3. ترفع الإدارة الملف من لوحة Homi Admin إلى `POST /api/v1/admin/activation-requests/import`.
4. تتحقق المنصة من صيغة HREQ وتوقيع Ed25519 وبصمة المفتاح، ثم تنشئ سجل طلب في D1 وتحفظ الملف في التخزين الخاص.
5. تراجع الإدارة الطلب وتحدد الخطة والمقاعد وتؤكد استلام الدفع اليدوي.
6. تصدر المنصة ملف `.hlic` موقعًا بمفتاح Ed25519 خاص بالخادم.
7. ترسل الإدارة الملف للعميل، ويستورده التطبيق ويتحقق منه Offline.

## وظائف مؤجلة

- إنشاء طلب التفعيل المباشر من التطبيق.
- إثبات ملكية الجهاز عبر تحدٍ من API.
- متابعة حالة الطلب أو تنزيل الترخيص من داخل التطبيق أو الموقع.
- تسجيل التجربة المحلية مركزيًا.
- تجديد تصاريح Offline Grants عبر تحدٍ شبكي.
- رفع إثبات الدفع من واجهة العميل.

هذه المسارات لا تُحذف من المصدر في هذه المرحلة؛ لكنها محمية بمفتاح `ONLINE_ACTIVATION_ENABLED` الذي يكون معطلًا افتراضيًا، وتعيد HTTP 410 ما لم تضبطه الإدارة صراحةً على `true`. لا تُفعّل مجددًا دون مراجعة مستقلة واختبارات توافق.

## تحديثات التطبيقات

تحديثات OTA منفصلة عن التفعيل والاشتراك، وتظل ضمن نطاق المنصة الحالي. يستخدم التطبيق Keyset وmanifest موقعًا ويتحقق من الحجم وبصمة SHA-256 قبل التثبيت. تأجيل التفعيل عبر الإنترنت لا يعني إيقاف OTA.

## مكونات البنية

| الخدمة | الاستخدام |
|---|---|
| Cloudflare Pages Functions | API ولوحة الإدارة والموقع في بيئات منفصلة |
| D1 | بيانات العملاء والأجهزة والطلبات والاشتراكات والمدفوعات والتراخيص |
| Backblaze B2 | ملفات الطلبات وإثباتات الدفع وحزم الإصدارات وفق إعداد التخزين الحالي |
| Cloudflare Access | حماية لوحة الإدارة وواجهات الإدارة |
| GitHub Actions | التحليل والاختبارات وبناء التطبيقات |

لا يستخدم النظام Neon أو Firebase أو Supabase أو PostgreSQL خارجيًا.

## نموذج المجال

Customer 1:N Subscription 1:N License N:1 Device.

الاشتراك يحدد عدد المقاعد. كل جهاز معتمد يحصل على ترخيص منفصل مربوط ببصمة مفتاحه العام. لا يسمح ملف ترخيص واحد بتجاوز عدد الأجهزة.

## مبادئ البيانات والأمان

- لا تنتقل بيانات المبيعات أو المخزون أو الديون أو قاعدة SQLite المحلية إلى المنصة.
- تخزن المنصة بيانات العميل الضرورية لإدارة الاشتراك فقط.
- كل التواريخ تحفظ UTC بصيغة ISO-8601.
- جميع تغييرات الترخيص والمدفوعات والأجهزة الحساسة يجب أن تنتج سجل تدقيق.
- لا يُصدر ترخيص مدفوع ولا يمدد قبل تأكيد الإدارة استلام المبلغ.
- مفاتيح التوقيع الخاصة تبقى في أسرار الخادم فقط؛ التطبيق يحتوي المفاتيح العامة اللازمة للتحقق.
- لا تنشأ موارد Production ولا تُنشر دون موافقة صاحب المشروع.
