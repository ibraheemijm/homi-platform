# معمارية Homi Platform

## حدود المسؤولية

- **Homi Website:** موقع عام، صفحات تعريف وتنزيل، رفع ملف طلب `.hreq`، ومتابعة حالة الطلب بواسطة رمز الطلب.
- **Homi Admin:** مساحة إدارية محمية داخل مشروع المنصة؛ لا توجد حسابات للعملاء.
- **Homi Platform API:** Cloudflare Worker، مسؤول عن التحقق من الطلبات وإدارة الاشتراكات والأجهزة والتراخيص.
- **Homi Grocery:** تطبيق قائم. نطاق التغيير فيه محصور في الاشتراك والتفعيل وواجهاتهما.

## مكونات Cloudflare

| الخدمة | الاستخدام |
|---|---|
| Workers | API العامة والإدارية |
| D1 | البيانات العلائقية |
| R2 | ملفات التثبيت والتحديث وطلبات التفعيل ومرفقات الدفع |
| KV | كاش قصير العمر عند الحاجة فقط |
| Queues | مهام خلفية عند الحاجة المثبتة |
| Durable Objects | تنسيق حصري عند وجود حالة متزامنة لا تكفي D1 لمعالجتها |

لا يستخدم النظام Neon أو Firebase أو Supabase أو PostgreSQL خارجيًا.

## نموذج المجال

Customer 1:N Subscription 1:N License N:1 Device.
الاشتراك يحدد عدد المقاعد. كل جهاز معتمد يحصل على ترخيص منفصل مربوط ببصمة مفتاحه العام. لا يسمح ملف ترخيص واحد بتجاوز عدد الأجهزة.

الطلب قد ينشأ من التطبيق مباشرة أو من رفع ملف `.hreq` أو من الموقع. جميع المسارات تنتهي في سجل طلب موحد مع مصدر الطلب.

## التفعيل الحالي المتوافق مع Grocery

تتطابق المرحلة الأولى مع المسارات التي يستخدمها الفرع `feature/manual-activation-no-account` في Homi-Grocery:
- `POST /api/v1/public/activation-requests`
- `POST /api/v1/public/activation-requests/{id}/proof`
- `GET /api/v1/public/activation-requests/{id}/status`

إثبات الجهاز يستخدم رسالة UTF-8 مرتبة ومحددة:
`HOMI_DEVICE_PROOF_V1\n{request_id}\nhomi-grocery\n{platform}\n{architecture}\n{challenge}`
ويتم التحقق من توقيع Ed25519 بالمفتاح العام المرسل في الطلب.

## مبادئ البيانات

- لا تنتقل بيانات المبيعات أو المخزون أو الديون أو قاعدة SQLite المحلية إلى المنصة.
- تخزن المنصة بيانات العميل الضرورية لإدارة الاشتراك فقط.
- كل التواريخ تحفظ UTC بصيغة ISO-8601.
- جميع تغييرات الترخيص والمدفوعات والأجهزة الحساسة يجب أن تنتج سجل تدقيق.
- عمليات إصدار الترخيص والتجديد يجب أن تكون idempotent.
