# إعداد الدخول الإداري

تستخدم لوحة Homi Admin مصادقة Cloudflare Access، ثم يتحقق Worker من JWT مرة أخرى، ثم يطبق D1 RBAC. لا توجد كلمات مرور أو جلسات عملاء في قاعدة بيانات Homi.

## متغيرات Worker

- `CF_ACCESS_TEAM_DOMAIN`: أصل فريق Cloudflare Access مثل `https://team-name.cloudflareaccess.com`.
- `CF_ACCESS_AUD`: Audience Tag الخاص بتطبيق Access الذي يحمي API.
- `ADMIN_SITE_ORIGIN`: أصل واجهة الإدارة المسموح به في CORS.
- `PUBLIC_SITE_ORIGIN`: أصل الموقع العام.
- `LICENSE_SIGNING_KEY_ID`: معرف مفتاح توقيع الترخيص.
- `LICENSE_SIGNING_PRIVATE_KEY_PKCS8_B64`: Worker Secret يحتوي PKCS#8 DER مشفرًا بـBase64. لا تضعه في GitHub أو تطبيق العميل.

يقرأ Worker ترويسة `Cf-Access-Jwt-Assertion` ويتحقق من التوقيع عبر JWKS الخاص بفريق Access ومن `iss` و`aud` قبل قراءة البريد الإلكتروني. لا يثق في ترويسة بريد غير موقعة أو في JWT مفكوك دون تحقق.

## تسجيل أول مدير

بعد إعداد D1 وCloudflare Access، يضاف المستخدم الأول يدويًا عبر قناة إدارية آمنة إلى جدول `admin_users` مع `role_key = 'owner'`. لا تضع بريدًا شخصيًا أو معرفات حسابات فعلية في ملفات المستودع أو أمثلة SQL عامة.

يجب أن يطابق البريد الإلكتروني المسجل في D1 البريد الذي يصدره موفر الهوية بعد نجاح Access. الحسابات غير المسجلة أو المعطلة تُرفض حتى لو نجحت المصادقة لدى Access.

## الصلاحيات

- `owner`: جميع الصلاحيات.
- `administrator`: إدارة العمليات، دون إدارة حسابات الإدارة.
- `support`: مراجعة طلبات التفعيل والأجهزة وبيانات العملاء.
- `finance`: تأكيد استلام المدفوعات وإدارة الاشتراكات المالية.
- `release_manager`: إدارة التطبيقات والإصدارات.

الموافقة على طلب وإصدار ترخيص تتطلب الصلاحيات التالية مجتمعة:
`activation_requests.review`, `payments.confirm`, `subscriptions.manage`, `licenses.issue`.

## حدود التنفيذ الحالية

أصبحت لوحة الإدارة تشمل الآن مسارات التشغيل الأساسية التالية، إضافة إلى المسارات الأولية:

- إدارة طلبات التفعيل: عرض الطلبات، تحويلها للمراجعة، واعتماد الطلب وإصدار الترخيص.
- إدارة إثباتات الدفع: عرض قائمة الإثباتات، فتح الإيصال الخاص، وتأكيد الاستلام أو رفض الإثبات.
- إدارة العملاء: البحث، عرض ملف العميل والاشتراكات والأجهزة والمدفوعات، وتعديل بيانات التواصل مع سجل تدقيق.
- إدارة الاشتراكات: تعديل سعة الأجهزة، ربط جهاز جديد بعد إثبات الملكية، إيقاف الاشتراك أو إعادته ضمن شروط الصلاحية، وتجديد الاشتراك الشهري أو السنوي مع تسجيل دفعة يدوية مؤكدة.
- إدارة الأجهزة: الإيقاف وإعادة التفعيل والإلغاء النهائي وفق الصلاحيات.
- إدارة الإصدارات: إنشاء المسودات، رفع الحزم متعددة الأجزاء، إكمال الرفع، النشر والسحب.

كل عملية محمية تتحقق من JWT الخاص بـ Cloudflare Access ثم صلاحيات RBAC في D1. وتُسجل التغييرات الحساسة في سجل التدقيق. التفاصيل الدقيقة للطرق والحقول والصلاحيات موثقة في `docs/API_CONTRACTS.md`.

لا توجد بوابة دفع إلكتروني؛ تأكيد الدفع يدوي، ولا يصدر الترخيص أو يجدد الاشتراك اعتمادًا على إيصال مرفوع وحده.

## قبل النشر

- أنشئ تطبيق Access منفصلًا لواجهة الإدارة وآخر لواجهة API أو استخدم إعدادًا يضمن أن JWT المرسل إلى API يحمل Audience الصحيح.
- احصر سياسة Access في حسابات الإدارة المعتمدة.
- لا تعتبر حماية واجهة الإدارة وحدها كافية؛ Worker يتحقق من JWT وRBAC.
- اختبر مستخدمًا مسجلًا، مستخدمًا غير مسجل، مستخدمًا معطلًا، وكل دور بصلاحياته.
- أضف الأسرار باستخدام `wrangler secret put` في بيئة كل Worker بعد توليد المفتاح محليًا. لا تنفذ هذه الخطوة قبل تحديد بيئة Cloudflare المعتمدة وموافقة النشر.
